# Vision（产品愿景）

> BeWater 项目北极星 | 创建日期：2026-05-05
> 生成方式：/bewater-init Vision Discovery 对话式引导
> 用途：定义项目方向、判断标准和边界；不是 PRD，也不是排期 roadmap。

## Project Mode（项目类型）

- 类型：internal
- 选择原因：第一阶段服务内部内容团队，用 AI 补足短视频策划、编导、剪辑和运营能力，先验证真实生产效率和成片质量，再考虑外部产品化。

## Core Intent（核心动机）

小团队缺少专业短视频策划、编导、剪辑和运营人才时，很难稳定完成从选题到成片的生产。这个项目要把知识分享短视频的生产流程标准化、自动化，让内容团队输入主题、文案或链接后，得到可预览和下载的可发布初稿，把人工时间从从零策划和剪辑转移到审核和小改。

## One-liner（一句话描述）

我们正在为内部内容团队做短视频自动化生产平台，帮助他们在缺少专业短视频策划和剪辑支持的情况下，从主题、文案或链接快速生成知识分享类短视频初稿。

## Target User（目标用户）

### Primary User

- 用户：内部内容团队成员。
- 典型场景：他们有文章、观点、主题或参考链接，需要稳定产出知识分享短视频，但没有足够的短视频策划、编导和剪辑能力。
- 为什么先服务他们：他们能提供真实内容输入和反馈，痛点集中在文案、素材匹配、字幕、封面和成片生产闭环，最适合验证自动化是否节省时间。

### Secondary User

- 用户：创始人、业务负责人、运营人员。
- 说明：他们也会受益，但第一阶段不优先围绕个人表达或账号运营策略定制能力。

### Not For

- 通用剪辑师：本项目不做自由时间线剪辑器。
- 需要自动发布和账号运营全托管的团队：第一阶段只到可发布初稿，不做自动发布。
- 无素材使用权要求的素材搬运场景：第一阶段假设用户对输入链接素材拥有使用权或授权。

## Core Problem（核心问题）

- 场景：团队需要把文章、观点、主题或参考视频快速转成短视频。
- 当前痛点：人工流程需要研究同类视频、判断选题、写短视频稿、找素材、匹配画面、生成配音、加字幕、做封面并剪辑，耗时且依赖专业人才。
- 影响：没有专业人才时产出不稳定；有专业人才时也会被重复剪辑和素材匹配消耗大量时间。

## Current Alternative（当前替代方案）

用户现在通常会这样解决：

- 人工研究同类视频、做选题、写稿、找素材、剪辑、配字幕、配音和封面 — 不足：链路长、体力活多、对短视频经验依赖强。
- 使用 ChatGPT 写稿，再用剪映等工具手动找素材和剪辑 — 不足：文案到画面匹配仍需人工处理，不能形成完整生产闭环。
- 依赖剪辑或运营外包 — 不足：沟通成本高，产出节奏和质量不稳定。

## Core Promise（核心承诺）

用户以前：
> 需要从零研究、写稿、找素材、配音、加字幕、做封面和剪辑，才能得到一条知识分享短视频。

用户以后：
> 输入主题、文案或链接，并提供相关素材链接后，可以得到可预览、可下载、接近直接发布的视频初稿，人工主要负责审核和小改。

## Narrowest Wedge（最小切口）

第一版只证明：
> 知识分享类短视频可以从主题、文案或链接，加上用户提供的素材链接，自动生成可发布初稿。

第一版不证明：
> 通用剪辑器、全网自动搜素材、版权合规自动判断、自动发布、口播视频自动剪辑、产品介绍视频自动生产。

## Product Principles（产品原则）

后续做 feature 时必须遵守：

1. Workflow Over Editor：优先做标准化视频生产流程，不做通用时间线剪辑器。
2. Reviewable Automation：自动化产物必须可预览、可追溯、可人工小改；第一版不追求完全无人值守。
3. Rights-Aware Inputs：第一版允许直接使用用户提供链接素材，但产品边界必须明确用户负责素材使用权，系统不承诺自动版权判断。
4. Skill-Based Capability Reuse：Agent 负责判断，Skill 负责可复用能力；新增视频类型应优先组合已有 Skills，而不是复制整条流程。
5. Time Saved Must Be Visible：所有核心功能都要能证明是否减少人工策划、素材匹配和剪辑时间。

## Direction（方向，不是排期）

### Now

现在最重要的是验证：
- 知识分享类短视频从输入到可发布初稿的自动化闭环。
- 编导 Agent 能否生成可用短视频文案和分镜意图。
- 素材匹配能否让旁白、字幕和画面在语义上基本对齐。
- Reviewer Agent 能否发现明显文案、事实、字幕、素材匹配和成片质量问题。

### Next

如果 Now 被验证，下一步增强：
- 口播视频自动剪辑：上传口播原片后自动剪辑、配字幕、做封面并输出完整口播视频。
- 更细的人工审核和重试节点。
- 更稳定的素材片段选择、替换和人工调整能力。

### Later

长期可能发展，但现在不承诺：
- 产品介绍视频：输入产品名或简介，生成讲解文案、配音、字幕，并匹配产品相关视频素材。
- 授权素材库、版权检测、自动发布和账号运营建议。
- 多视频类型的模板市场或外部商业化平台。

## Non-goals（当前不做什么）

- 不做通用剪辑器 — 因为核心价值是自动化生产工作流，不是替代专业剪辑软件。
- 不做全网自动搜索并使用素材 — 因为版权、质量和稳定性风险过高，第一版以用户提供链接为边界。
- 不做自动发布 — 因为第一版必须保留人工审核和小改。
- 不做复杂多 Agent 编排平台 — 因为第一阶段只需要编导、审核和线性 Skill Pipeline。
- 不做口播和产品介绍完整实现 — 因为第一版聚焦知识分享最小闭环。

## Success Signals（成功信号）

1. 内容团队能从主题、文案或链接，加上素材链接，生成一个可预览和下载的视频初稿。
2. 人工只需要审核和小改，不需要从零写稿、找素材、配音、加字幕、做封面和剪完整视频。
3. 单条知识分享短视频的制作时间相比当前人工流程下降至少 70%。
4. Reviewer Agent 能输出可执行的问题清单，而不是泛泛评价。
5. 生成结果中旁白、字幕和画面素材的匹配问题可被定位到具体片段。
6. 系统保留关键中间产物，内容团队能在文案、分镜、配音、字幕、素材匹配、封面和成片阶段定位问题并重试。

## Open Assumptions（开放假设）

- 用户提供的视频链接可被系统下载或解析；若链接平台限制下载，需要支持用户上传素材或人工导入作为替代。
- 用户对输入素材拥有使用权或授权；系统第一版不承担自动版权判断。
- 第一版生成的视频质量只需达到可发布初稿，不要求完全免人工修改。
- 外部 LLM 和 TTS API 的成本、速度和稳定性足以支撑内部使用。
