# 错误处理策略

> **版本**: 1.0.0
> **目的**: 定义 BeWater 方法论中各类错误的分类、处理策略和恢复机制
> **适用范围**: 所有 Skill 和 Agent

---

## 错误分类体系

### 一级分类（按来源）

| 分类 | 说明 |
|------|------|
| **系统错误** | BeWater 系统设计问题（Agent 调用、权限、状态同步） |
| **人为错误** | 用户操作问题（流程遵循、环境配置） |
| **外部错误** | 第三方依赖问题（API、服务） |

### 二级分类（按类型）

| 类型 | 处理策略 | 示例 |
|---------|---------|------|
| 权限拒绝 | 交互式处理 | Agent tool 调用被拒绝 |
| 文档缺失 | 降级处理 | feature.md 不存在 |
| 依赖失败 | 标记阻塞 | 前置任务未完成 |
| 超时 | 重试机制 | Agent 执行超时 |
| 返回格式错误 | 容错处理 | JSON 解析失败 |
| 状态冲突 | 冲突检测 | state.json 并发修改 |

---

## 详细处理策略

### E-1: 权限拒绝

**描述**: Agent tool 调用被用户拒绝

**检测方式**:
- Agent tool 返回包含 "user denied" 或 "permission denied"

**处理策略**:

| Agent 类型 | 拒绝后处理 |
|-----------|-----------|
| **必需 Agent** | 暂停，提供重试/跳过/取消选项 |
| **可选 Agent** | 记录警告，继续执行 |

**实现示例**:

```markdown
## 权限拒绝处理

检测到 Agent 调用被拒绝：

**必需 Agent**：
```
⚠️ [Agent Name] 调用被拒绝

这是必需步骤，请选择：
1. 重新请求授权
2. 跳过并记录技术债务
3. 取消操作
```

**可选 Agent**：
```
⚠️ [Agent Name] 调用被拒绝（可选）

将继续执行，但已记录为技术债务。
```
```

**必需 Agent 定义**:
- Reviewer Agent（Critical/High 风险）
- QA Agent（发布前，含安全/性能）

---

### E-2: 文档缺失

**描述**: 所需文档不存在或未填写

**检测方式**:
- Read tool 返回文件不存在
- 文件存在但占位符 > 5 个

**处理策略**:

| 场景 | 处理方式 |
|------|---------|
| **项目级文档缺失**（vision.md, architecture.md） | 引导运行 /bewater-init |
| **功能级文档缺失**（feature.md） | 提供自动创建模板选项 |
| **任务文档缺失**（tasks.md） | 提示运行 /bewater-plan |

**实现示例**:

```markdown
## 文档缺失处理

检测到 docs/01-features/{编号}/feature.md 不存在。

请选择：
1. 自动创建模板文件（推荐）
2. 手动创建后继续
3. 取消操作

输入选项 [1/2/3]:
```

---

### E-3: 依赖失败

**描述**: 前置步骤未完成或依赖任务失败

**检测方式**:
- state.json 中前置状态不匹配
- tasks.md 中依赖任务状态为 blocked 或 failed

**处理策略**:

| 场景 | 处理方式 |
|------|---------|
| **状态不匹配** | 提示先运行缺失的步骤 |
| **任务被阻塞** | 显示阻塞链，等待解除 |
| **任务失败** | 提示修复失败任务 |

**实现示例**:

```markdown
## 前置状态检查

当前状态：building
期望状态：planned

请先运行 /bewater-plan {编号} 生成任务清单。
```

---

### E-4: 超时

**描述**: Agent 执行时间超过预期

**检测方式**:
- Agent 执行时间 > 5 分钟（可配置）

**处理策略**:

| 场景 | 处理方式 |
|------|---------|
| **首次超时** | 自动重试 1 次 |
| **重试仍超时** | 标记超时，提供选项 |

**实现示例**:

```markdown
## 超时处理

Agent 执行超时（> 5 分钟）。

请选择：
1. 继续等待
2. 取消并重试
3. 跳过此步骤

输入选项 [1/2/3]:
```

---

### E-5: 返回格式错误

**描述**: 子代理返回的 JSON 格式不符合预期

**检测方式**:
- JSON 解析失败
- 缺少必需字段

**处理策略**:

| 场景 | 处理方式 |
|------|---------|
| **JSON 解析失败** | 记录原始输出，使用默认值 |
| **缺少必需字段** | 使用默认值，记录警告 |

**实现示例**:

```markdown
## 返回格式错误处理

⚠️ 子代理返回格式错误

期望: {"status": "passed", ...}
实际: [原始输出]

已使用默认值继续执行。
请检查子代理日志。
```

---

### E-6: 状态冲突

**描述**: state.json 被并发修改

**检测方式**:
- 读取后，last_updated 时间戳发生变化

**处理策略**:

| 场景 | 处理方式 |
|------|---------|
| **检测到冲突** | 提示用户，重新读取后写入 |

**实现示例**:

```markdown
## 状态更新冲突检测

## vNext Release/Gate Drift Rules

- `/bewater-plan` writes `prebuild_review_gate`
- `/bewater-build` writes `review_gate`
- `/bewater-ship` writes `ship_precheck_gate`
- `release_execution_failure` keeps release readiness in `building.ready_to_ship`
- stale gates come from digest / artifact drift, not from infra failure alone

⚠️ state.json 在读取后被修改

读取时间: 2026-04-01 10:00:00
当前时间: 2026-04-01 10:00:15

请选择：
1. 重新读取并合并
2. 强制覆盖
3. 取消

输入选项 [1/2/3]:
```

## 并行调用错误处理

### 部分成功场景

当并行调用多个验证维度时：

| 场景 | 处理方式 |
|------|---------|
| **全部成功** | 合并所有维度结果 |
| **部分失败** | 记录失败项，合并成功结果，标记"部分完成" |
| **全部失败** | 标记"验证失败"，提供详细错误信息 |

### 实现模板

```markdown
## 并行调用失败处理

等待所有 Agent 完成后：

1. **收集结果**：
   ```python
   results = {
     "qa": "passed",
     "security": "passed",
     "performance": "failed"
   }
   ```

2. **判断场景**：
   - 全部 passed → overall_status = "passed"
   - 部分 passed → overall_status = "partial"
   - 全部 failed → overall_status = "failed"

3. **输出结果**：
   - 输出 QA 报告中的 qa/security/performance 维度结论
   - 记录失败的原因
   - 提供修复建议
```

## 降级策略

### 降级场景

| 正常流程 | 降级流程 | 触发条件 |
|---------|---------|---------|
| 文档存在，正常读取 | 自动创建模板 | 文档缺失 |
| Agent 调用成功 | 跳过并记录债务 | 权限拒绝 |
| 所有测试通过 | 标记警告继续 | 非关键测试失败 |

### 降级记录

所有降级操作必须记录到 `decision-log.md`：

```markdown
## 降级记录

**日期**: 2026-04-01
**操作**: [降级操作描述]
**原因**: [触发原因]
**影响**: [对项目的影响]
**后续行动**: [如何恢复正常流程]
```

## 错误报告格式

### 用户可见格式

```markdown
❌ [错误类型]

[错误描述]

**影响**: [对当前操作的影响]

**建议修复**:
1. [修复步骤 1]
2. [修复步骤 2]

**技术细节**:
- 错误代码: [E-1, E-2, ...]
- 发生时间: [ISO8601]
- 相关文件: [文件路径]
```

### 日志格式

```json
{
  "timestamp": "2026-04-01T10:00:00Z",
  "error_type": "E-1",
  "error_code": "PERMISSION_DENIED",
  "message": "Agent tool call denied by user",
  "context": {
    "agent": "reviewer",
    "feature": "001"
  },
  "recovery_action": "prompt_user"
}
```

## 预防性检查

### 执行前检查清单

每个 Skill 在执行前应检查：

- [ ] 前置状态是否匹配
- [ ] 必需文档是否存在
- [ ] 依赖任务是否完成
- [ ] 环境配置是否完整

### 环境检查

创建 `templates/core/environment-checklist.md`:

```markdown
## 项目初始化环境检查

- [ ] Python 测试框架配置（pytest）
- [ ] 前端测试框架配置（Jest + RTL）
- [ ] 环境变量文件（.env.example）
- [ ] PYTHONPATH 配置
- [ ] 数据库测试配置
```
