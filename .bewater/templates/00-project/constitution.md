# 项目宪法（Project Constitution）

> 定义项目的不可变原则。所有功能开发和架构决策必须遵守这些原则。
> 由 /bewater-init 在初始化时通过对话生成。

---

## 默认原则说明

以下 5 条原则是 BeWater 方法论默认原则，适用于大多数项目。`/bewater-init` 阶段三会引导用户确认这些原则是否适合当前项目，用户可以：
- 直接采纳全部默认原则
- 删除不适用的原则
- 新增项目特有的原则

原则数量建议 3-7 条，过多会降低可执行性。

---

## 不可变原则

### 原则 1: Evidence-First Delivery（证据先行）

**描述**:
所有实现必须有可追溯的证据链：TDD receipt（测试先于实现）、可运行的测试命令、validation evidence（验证报告）。没有测试覆盖的代码不算完成，没有验证证据的功能不可发布。证据是 go/no-go 决策的唯一依据。

**合规检查**:
- [ ] 每个实现任务都有对应的测试（先写测试，后写实现）
- [ ] 测试可通过 `npm test` / `pytest` / 等标准命令一键运行
- [ ] validation-report.md 包含可追溯的测试结果证据

### 原则 2: User-Visible Slice First（用户价值切片优先）

**描述**:
每次交付优先形成用户可感知、可验证的价值切片，而非底层基础设施或内部重构。如果一项工作不能直接或紧密关联到用户可见的行为变化，应推迟或作为更大切片的附属任务。优先切出"最小可验证闭环"。

**合规检查**:
- [ ] 每个 feature.md 的 MVP scope 包含用户可直接观察的行为
- [ ] tasks.md 的首个执行块（Execution Block）产出的增量是用户可验证的
- [ ] 纯基础设施任务附属于某个用户价值切片，不独立交付

### 原则 3: Simplicity Over Speculation（简约优于猜测）

**描述**:
不为假设的未来需求添加抽象层、配置项、模块划分或流程步骤。三行相似代码优于一个过早抽象。当复用需求真实出现时再重构，而不是提前设计。每多一层间接层，都必须用当前需求的复杂性来证明其必要性。

**合规检查**:
- [ ] 新增的抽象层/接口/配置项有当前需求的明确依据
- [ ] 没有为"以后可能需要"而预留的空模块或 placeholder 接口
- [ ] design.md 中每个设计决策都可追溯到当前功能需求

### 原则 4: Use Existing Architecture Directly（直接沿用现有架构）

**描述**:
优先使用项目已有的框架、目录结构、helper 函数和约定，而不是引入新的包装层、工具库或架构模式。如果现有架构能满足需求，就用它；如果不能满足，先在 design.md 中说明原因，再引入变更。变更必须是有意的、有记录的，而非无意识的偏好。

**合规检查**:
- [ ] 新代码使用已有框架/目录/helper，而非引入等效的新抽象
- [ ] 如需引入新依赖或新架构模式，design.md 中有明确的理由记录
- [ ] decision-log.md 记录了架构偏离决策

### 原则 5: Boundary Validation（边界验证）

**描述**:
用户可见的行为必须通过真实边界验证——CLI 命令、API 端点、UI 交互、E2E 测试或 blackbox smoke 测试均可。纯单元测试不足以证明功能完整。验证必须在真实或接近真实的环境中执行，确保边界两侧的契约正确。功能边界清晰是前提；只有真实复用或复杂度需要时才抽取模块。

**合规检查**:
- [ ] 每个用户可见行为至少有一个边界级测试（API/E2E/CLI/smoke）
- [ ] 测试在真实或接近真实的环境中运行（非纯 mock 隔离）
- [ ] 功能边界在 design.md 或 tasks.md 中有明确定义

## 治理（Governance）

### 版本化

| 属性 | 值 |
|------|-----|
| 模板版本 | BeWater 4.0.0 默认 |
| 项目版本 | 1.0 |
| 创建日期 | YYYY-MM-DD |
| 最后更新 | YYYY-MM-DD |

### 同步检查

以下变更需要同步检查宪法一致性：
- `architecture.md` 变更 → 检查原则 4（沿用现有架构）是否受影响
- `design.md` 变更 → 检查原则 3（简约）和原则 5（边界验证）是否受影响
- `tasks.md` 变更 → 检查原则 1（证据先行）和原则 2（用户价值切片）是否受影响

同步检查在 `/bewater-validate` 阶段的 Constitution Alignment 部分自动执行。
